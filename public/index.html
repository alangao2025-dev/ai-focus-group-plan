自建「AI 模拟用户焦点小组」产品方案

多个 AI 扮演不同画像的用户，再加一个 AI 主持人，围绕一个产品展开讨论，最后输出产品优化方向和推广策略。

示例场景：Javis 用户访谈多 Agent 角色扮演焦点小组市场调研
一、整体结构 二、四个模块 三、难点与对策 四、分三步做 五、技术选型 六、差异化 七、与 FGD 手册结合 八、下一步

1整体结构

输入：产品资料（Javis 介绍、功能、价格）+ 研究目标（例如“找出高净值用户最在意的功能和获客渠道”）
输出：完整讨论记录 + 产品优化建议 + 推广策略（每条结论都可追溯到原话）
① 画像生成5–8 个差异明显的虚拟用户
→
② 访谈提纲主持人按研究目标生成
→
③ 讨论引擎主持人 + N 个用户多轮讨论
→
④ 分析报告优化方向 + 推广策略
整个产品就是一个调度程序，反复调用大模型 API（Claude、GPT、DeepSeek 等），每个角色用各自的提示词，加上一个控制谁先说、说几轮的流程。

2四个模块怎么做

模块 ①

画像生成

  • 每个画像用一份 JSON 描述：年龄、职业、收入、使用场景、痛点、现在用的替代品、性格（挑剔还是随和）、价格敏感度、获取信息的渠道。
  • 来源：用户手写；或者由 AI 根据“目标人群描述”一次生成多个画像；进阶做法是用真实的问卷、评论、社交媒体数据生成，结果更可信。
  • 关键：画像之间差别要大。刻意放进反对者、价格敏感型、竞品忠实用户，不能全是会买的人。
{
  "name": "王总", "age": 48, "role": "制造业企业主",
  "income": "年收入 500 万+", "scenario": "出差多，日程和家务靠秘书",
  "pain": ["信息太杂", "不放心把隐私交给 App"],
  "alternatives": ["私人秘书", "微信备忘"],
  "personality": "挑剔、讲结果、没耐心",
  "price_sensitivity": "低", "channels": ["圈子推荐", "商学院同学"]
}
模块 ②

主持人 Agent

  • 输入产品介绍和研究目标，先生成访谈提纲：
    暖场 → 使用现状 → 痛点 → 看产品概念 → 付费意愿 → 推荐意愿
  • 讨论中，主持人每一轮决定三件事：
    • 下一个问题问什么
    • 点谁回答
    • 要不要追问分歧（“A 说很好用，B 不同意，B 你具体说说”）
  • 保持中立，不能引导用户说好话。
模块 ③ · 核心

讨论引擎

维护一份全场共享的讨论记录，每个用户 Agent 发言前都能看到前面所有人说了什么。

  1. 主持人提问
  2. 每个用户先单独、不看别人地作答，减少互相附和
  3. 公开所有回答，被点到的用户依次回应、反驳
  4. 主持人判断：追问分歧，还是进入下一题
  5. 提纲走完或到设定轮数后结束
每个用户的提示词都要写死：“你是×××，始终按这个人的身份、认知水平和说话方式发言，不知道的就说不知道，不要客气、不要总是赞同。”
模块 ④

分析与报告

讨论结束后，交给一个独立的“分析师 Agent”读完整份记录，输出：

  • 共识点、分歧点，按不同画像分别列出各自的态度
  • 痛点排序 → 产品优化方向
  • 购买理由和顾虑、信息渠道、触动他们的话术 → 推广策略
  • 每条结论都标注出自哪段原话，方便追溯
用 JSON 结构化输出，再渲染成网页报告或 PDF。

3最难的几个问题（决定产品好不好用）

问题表现对策
大家都太客气所有人都说“挺好的”提示词里要求说真话、给负面意见设配额；先单独作答再讨论；加入反对者画像
画像说着说着变样说到后面口吻全一样每轮都重新注入画像设定；不同角色用不同模型或不同 temperature
结论是编的报告里出现没人说过的观点报告必须引用原话，并用程序检查引用是否真实存在
结果不稳定跑两次结论不一样同一场讨论跑 3–5 次，只采纳反复出现的结论
成本高8 个人 × 20 轮，消耗大量 token历史记录做摘要压缩；用户发言用便宜的模型，主持人和分析师用强模型
这类模拟结果适合用来找方向、列假设，不能代替真实用户访谈。关键结论最好再找少量真人验证。

4建议分三步做

第 1 步 · 原型 · 1–2 天

验证结果有没有价值

  • 一个 Python 脚本：3 个画像 + 1 个主持人 + 5 道题，输出 Markdown 报告。
  • 可以直接用 Microsoft TinyTroupe（开源，自带焦点小组示例），也可以自己写，自己写大约 300 行。
  • 用 Javis 跑一次，看看结论有没有价值。
第 2 步 · MVP · 1–2 周

做成可用的网页

  • 用户可以输入产品信息、编辑画像
  • 实时观看讨论（逐字流式输出）
  • 讨论结束后生成报告
  • 用数据库保存项目和讨论记录
第 3 步 · 产品化

做成能卖的产品

  • 画像库（按行业预置）
  • 导入真实数据（问卷、评论、社交媒体）生成画像
  • 多次运行汇总，提高结论稳定性
  • 导出 PPT、多语言、账号体系与付费

6差异化方向（相对现有产品）

🇨🇳 中文场景深耕

现有产品里只有 atypica 是原生中文。可以做中国用户画像库，加上小红书、抖音风格的推广建议。

✅ 结果可以验证

给出“模拟结论 vs 真实用户调研”的对比，这是用户最在意的可信度问题。

🚀 直接接执行

报告直接生成广告文案、落地页卖点、产品需求清单，从洞察直接到行动。

7与 FGD 手册的结合

把《焦点小组访谈（FGD）全流程实操手册》当成产品的方法论内核：主持人怎么问、画像怎么建、报告怎么写，都按专业 FGD 的规矩来。现有的 AI 焦点小组产品大多只是“几个 AI 聊天再总结一下”，这正是我们的差异化。

手册地址： https://fgd-guide.accrepo.com/

7.1 手册各章在产品里分别变成什么

手册章节产品功能用法
3.1 业务问题 → 研究问题
模板 A 研究 Brief		项目创建表单用户必须填三件事：要支持什么决策、有哪些决策选项、核心研究问题（最多 5 个）。AI 帮忙把模糊的业务问题拆成研究问题
3.2–3.3 组数、人数
组内同质、组间异质		分组配置自动建议分组（现用户、竞品用户、流失用户、潜在用户），每类人群至少跑 2 组，没有新主题出现（信息饱和）时就停
4.1 配额表
4.2 甄别问卷		画像生成的约束条件硬性条件和软配额直接变成画像生成规则：同组画像关键特征一致、次要特征有差异
5.1 漏斗结构和时间分配主持人提纲生成器按“热身 → 背景 → 行为 → 品牌 → 概念测试 → 总结”生成提纲，每个模块标“必须”或“可选”，按轮数分配（概念测试占 30–40%）
5.2 问题设计规则提纲自动检查自动标出诱导性问题、一次问两件事、“你会买吗”这类假设性问题，以及行业术语
5.3 投射技术主持人工具箱品牌拟人化、句子完成、品牌讣告、100 元预算分配等，主持人 Agent 按需调用
5.4 概念测试步骤讨论引擎的固定流程先个人书写（独立打分、写最喜欢和最不喜欢的一点），再小组讨论；多个概念按组轮换顺序
7.3 追问技巧主持人追问策略澄清、举例、阶梯法往深处追问、主动邀请不同意见，专门对付 AI 用户的空话套话
7.4 难缠受访者
7.5 群体偏差		画像行为特征 + 主持人控场部分画像设成主导者、沉默者、讨好者、爱面子的类型，讨论更像真人；主持人用手册话术控场
8.2 观察记录表
8.3 Debrief		每场自动复盘本场 3 个发现、和上一场的异同、意外发现、下一场追问重点
9.2–9.4 编码、框架矩阵、分析原则分析师 Agent 工作规范原文 → 初始编码 → 主题；生成“主题 × 组别”矩阵；区分用户主动提到的和被问到才说的
10.3 洞察公式报告模板每条洞察必须包含：观察到什么 + 原因 + 对产品意味着什么 + 建议怎么做
10.4–10.5 引语规范、局限性声明报告硬性规则每个结论配原话引用；禁止写百分比，只用“多数、部分、个别”；报告末尾自动附局限性声明
15 常见错误 Top 20项目质量检查清单项目跑完后自动对照检查，例如每类人群是否只跑了 1 组、是否用了百分比、有没有个人书写环节
7.2

要改写或删掉的部分

  • 用不上：场地、单向镜、礼金、签到核查、物料、执行日时间表（第 6 章、4.3–4.5）。
  • 改写：“防职业受访者” → 防 AI 同质化，检查画像是否太像、说话方式是否雷同。
  • 改写：“人均发言时间” → token 预算，同样用来倒推每场最多问几个问题。
  • AI 的毛病和真人很像：AI 爱讨好，对应手册说的社会期许和面子。7.5 节的对策（先写后说、问实际行为而不是态度、用第三人称提问）可以直接用来管 AI。
7.3

套到 Javis 上

  • 手册第 12 章建议高净值人群用 4–6 人的小组，Javis 的模拟组不要放 8 个人。
  • 分组：现用户、用私人秘书或助理的人、流失用户、潜在用户，每类至少 2 组。
  • 按 5.1 的漏斗走：先聊日常怎么管日程和家务，再看产品概念，最后聊推荐意愿和获客渠道（对应推广策略）。
7.4 · 更进一步

把模拟和真人访谈连起来

① 先模拟AI 跑 4–6 组，几分钟拿到一批假设
→
② 生成真人访谈材料按手册模板出 Brief、甄别问卷、讨论指南、知情同意书、观察记录表，重点放在分歧最大的问题上
→
③ 对比校准“模拟结论 vs 真人结论”，用来校准模拟画像
这样产品就从“AI 帮你猜”变成“AI 帮你把真实研究做得更快更准”，也能解决大家最担心的可信度问题。

8下一步

建议先做第 1 步原型，用 Javis 跑一场模拟访谈，讨论题分两类：

  • 产品优化方向：使用痛点、功能期望、现在用什么替代
  • 推广策略：信息来源、愿意付多少钱、什么情况下会推荐给别人

原型结论有价值，再投入做 MVP 网页。
